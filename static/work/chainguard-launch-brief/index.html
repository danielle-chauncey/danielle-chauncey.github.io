01 · The launch

Take first-party hardening and MCP from closed beta to GA.

What ships

  • Hardening-as-a-service for first-party skills. Teams submit the skills they write. Chainguard reviews, fixes, and returns each one with a HARDENING.md audit log.
  • Custom rulesets. Add org-specific rules on top of Chainguard's baseline.
  • Agent Skills MCP server. Agents query and pull the right skill on demand. When a skill is re-hardened, every agent gets the update.
skills.cgr.dev/<org>/<skill_name>:<version tag>

04 · Positioning
For platform and security teams whose developers write their own agent skills, Chainguard Agent Skills is the registry and hardening pipeline that fixes risky skills before an agent runs them, and keeps every agent on the current safe version.
05 · Message pillars, each with public proof

It fixes the skill

Every hardened skill ships with a HARDENING.md: each rule checked, what was found, what changed, and proof nothing material broke.

Chainguard blog, June 17, 2026

It stays current

Skills re-harden when the source changes or a rule is added. Through MCP, agents get the new version with no local copy to update.

Chainguard blog, June 17, 2026

Version discipline for agent behavior

Pin an agent to a skill SHA. Roll back when something breaks. Registry entitlements stay inside your org.

Chainguard blog, June 17, 2026

Your rules, on top of ours

Custom rulesets extend the baseline, which already targets over-permissioning, obfuscated commands, and credential harvesting.
