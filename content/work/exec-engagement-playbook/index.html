Executive Engagement
Program Playbook

How a central team runs executive meetings and side events at Northwind's flagship annual forum, from first invite to leadership debrief. Written so the team can run it without the author.
The one rule

Every engagement is one row. A 1:1 meeting and a hosted dinner live in the same table. Side events are a filtered view, not a second system. That is why one calendar can show a delegate's whole week, and why nothing has to sync between trackers.

How to read it

Each stage lists four facts: what triggers it, who owns it, where it lives, and what done looks like.

The stage structure is the reusable part. The forum details are the fill-in. To run a different program, keep the stages and swap the specifics.

Why it exists

Invites reach the program through many people, and the season peaks fast. The playbook puts intake, decisions, briefing docs, and reporting in one system the team owns. The program survives a handoff, and the debrief comes straight from the tracker.

Intake

One capture funnel
TriggerAn invite arrives. Volume peaks about six weeks before the event.
OwnerCoordination team.
WhereShared mailbox, then one catalog event and one engagement row per delegate.
DoneEvery invite is logged, accepted or not. Declines count in the reporting.
SourcesCustomers, partners, event hosts
→
Forwarded bySellers, assistants, executives: whoever got it first
→
Single funnelTeam shared mailbox
→
Tracker1 catalog event + 1 row per delegate

Most invites arrive forwarded. Hosts don't know the central team by name, so invites land with sellers and executives first. The shared mailbox is the one place they all converge, which makes it the funnel.

Log first, decide later. Log the event before anyone decides on it. One invite for three delegates becomes one catalog event and three linked engagement rows.

02

Review

Quality gate
TriggerA new invite is logged.
OwnerCoordination team.
WhereThe "Needs review" view on the engagements table.
DoneFields complete and routed to the right delegate team, or flagged and settled by a person.

Confirm six fields: event name, date and time, host, category, RSVP deadline, and which delegates it concerns. Automated intake fills most of them. Review catches what the automation flagged as unclear.

Decision

Approve, delegate, or decline
TriggerA reviewed invite needs a yes or no.
OwnerThe delegate team, together. CEO first. If not the CEO, a named delegate.
WhereThe same row. A decision is a status change plus the Exec field.
DoneStatus shows the decision. Exec shows who owns it.
DecisionSet statusSet execThen
ApproveIn progress→ Confirmed, hold sentCEOBriefing doc starts at ~95%

DeclineDeclined: meetingDeclined: eventNoneRow stays. The invite still counts.
HoldTBCNo responseNot scheduledNoneStays in queue. Reviewed weekly.
No separate approval step. Approval objects drift out of sync with the tracker. A status change on the row the team already works in does not.
The cascade: the CEO's and president's calendars firm up first. Their declines open slots that pass to other delegates. "Waiting room" is that handoff step, so the status itself tells the team a slot is moving. The coordination team sends the RSVP after the delegate team decides.

04

Briefing doc

Starts at ~95% confidence
TriggerAttendance is confirmed or about 95% likely.
OwnerBriefing writers, with core-team review.
WhereBriefing status and doc link, on the engagement row.
DoneStatus is Complete and the link is attached.

The 95% bar stops docs for events that fall through. Writing too early wastes the team's hours. Writing too late leaves the executive walking in cold.

Side events use a standard template, with attendee bios for small dinners. Briefing status rolls up to each delegate, so during prep the team can see which meetings still need a doc.

05

Event

The working calendar
TriggerEvent week.
OwnerDelegates and the coordination team, onsite.
WhereThe daily onsite calendar and per-delegate calendars.
DoneMarked attended. Onsite feedback captured.

Event week changes by the hour: late slots, backup meetings kept warm, declines that reshuffle a day. The calendars are where the team works. Status moves to Completed. Onsite feedback and final attendees go on the row for the debrief.

Four calendar views, one table

The team asked to keep calendars. Because every engagement is one row, each view is a filter.
All-upEvery engagement, colored by type.
Per delegateA delegate's whole week: meetings and side events together.
Side events onlyFiltered to type = side event.
Daily onsiteWhat is happening today, for the team on the ground.
Before you build them: a calendar needs a real start date-time field. If start time is stored as text, convert it first.

Annual reset

Structure and roster roll forward. Last year's rows do not. The old base is what you report from.
  1. Re-anchor the workback plan to next year's event dates.
  2. Roll the delegate roster forward. Archive last year's engagements.
  3. Clone the task workback.
  4. Keep last year's metrics for the year-over-year debrief.
  5. Point the intake automation at the new season's mailbox flow.
The repeatable skeleton
Intake one funnel→ Review quality gate→ Decision status + owner→ Prep at a confidence bar→ Event working calendar→ Metrics views, year over year

Take out the forum and this runs any executive engagement program: an advisory board, a briefing center, a conference presence. Define four things: the funnel, the decision statuses, the prep trigger, and the five numbers leadership wants. The patterns carry over as they are: one engagement object, views for separation, rollups for metrics, calendars for the working surface.

How this playbook was built

ChoiceThe rule behind it
Written for the operatorA playbook only the author can run is a diary. Every stage names an owner who isn't the author.
Four facts per stageTrigger, owner, where, done. If a stage can't fill all four, it isn't a stage yet.
One object, many viewsSeparate systems need syncing. Views of one table don't.
Decline rows stayThe debrief counts what the program turned down as well as what it took.
Open items in the docA handoff with hidden gaps fails in week one. Name them, with owners.
